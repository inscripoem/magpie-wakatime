# Implementation status

Source plan: PLAN.md. This file records the current state; the status paragraph at the end of PLAN.md section 10 describes the plan-time situation only.

## Delivered

0.1.5 runs from this directory with no build step and no dependencies: `package.json`, `index.mjs`, and the modules in `src/`, plus `README.md`, the plugin picture in `assets/` and behavior tests in `test/`. The plugin also returns an `auth` hook whose only method is an API key prompt, so the app's 插件 page and `magpie plugin login wakatime` can store the WakaTime key for it. Heartbeats name the agent (`entity`) instead of always reporting `magpie`; heartbeats sent before that change used the fixed value, and an existing host keeps the old mapping until it restarts. 0.1.2 splits cached input out of `ai_input_tokens`: heartbeats sent by 0.1.1 reported `in + cache_read + cache_write` as one uncached input total, and an existing host keeps that mapping until it restarts. The WakaTime mark shows on the plugin's 发现 card, its 已安装 row and the `wakatime` provider row: `package.json` inlines `assets/wakatime.png` as a `data:image/png;base64` URI in `magpie.icon`, since magpie takes an `https://` URL or a `data:image/` URI there and reads nothing from a path.

0.1.3 skips malformed source rows with a redacted diagnostic, counts only pending rows against queue capacity, and adds `authAccount` to bind a saved WakaTime sign-in. Multiple usable accounts require a binding. A missing bound account pauses synchronization; a changed key is read on the next tick.

0.1.5 reports the machine name, operating system and IANA timezone. Local gateway hooks capture project and branch names at request time and associate them with usage by client response ID. Missing context uses the configured project fallback. Explicit project mappings take priority, and raw working directories are not stored.

0.1.6 recognizes the canonical GitHub repository URL as an enabled installation, including `.git`, trailing-slash and ref-suffixed forms. This prevents the plugin from disabling itself after a URL-based install while retaining Magpie's explicit `off` behavior.

0.1.7 sends a `language` with each heartbeat instead of leaving WakaTime to file all AI usage under `Other`. The request hook reads the working directory's Git index, maps tracked extensions to WakaTime language names and stores the most common language with the project and branch. The scan reads file names only, skips vendored and generated trees, and is cached per directory in the plugin host; directories without a recognized language still send no `language` field.

## Unreleased: high-water cursor refactor (2026-11-03, worktree `experiment/write-jsonl`)

- The SQLite queue returns as the durable send queue (`queue.sqlite`, `src/queue.mjs`). `state.json` holds each day's `offset/head/tail/total/time` plus copies of `salt/gateway/enabledAt`; `identity.json` holds salt, gateway and first activation; `contexts.log` is an append-only request-context journal (project/branch/language plus raw response/session ids, local only, 10-minute TTL, compacted by threshold); `queue.sqlite` holds mapped heartbeat payloads plus acknowledged-id tombstones (3-day retention, deferred while an older backfill day is unfinished); `owner.lock/` is an exclusive lock directory whose `owner.json` carries owner, pid, host and acquisition time.
- Cursor and identity writes are temp file + rename with no fsync on the cursor; identity is fsynced once per activation. Cursor flushes repeat salt/gateway/enabledAt so either state file can restore them. A scan maps rows only after the pass's listing is stable (the head id is unchanged, the total does not decrease, and the processed tail rows remain in place, with no not-yet-processed id repeating within the pass; tail appends are allowed), commits the mapped payloads to the queue in a WAL/synchronous=FULL transaction, then advances the cursor, and only then drains the queue. Acknowledged entries (2xx or permanent 4xx) are marked in the queue and never re-sent; transient failures stay pending with backoff. A mid-scan listing shift discards that pass without enqueueing or advancing, so the pass is re-read. This assumes the gateway appends usage rows (the local store is `usage.jsonl`); a same-total rewrite of the middle of a completed day is outside the cursor's contract and needs that day's cursor reset.
- The lock replaces the 5-minute lease renewal: `mkdir` acquisition, same-host pid liveness for staleness, 10-minute TTL across hosts, no steady-state lock writes.
- `bun test`: 99 pass, 0 fail.
- Write volume: the durable queue changes the profile. Each scanned range is one enqueue transaction; each 25-row send batch is one ack transaction (WAL + synchronous=FULL), so commit count scales with send batches. `state.json` no longer changes per batch; it flushes for cursor/identity/diagnostic state (roughly once per scan pass). The queue bench (18,000 requests/day, 3 runs) measured `queue.sqlite` about 10.9 MB, its WAL about 4.2 MB, 4,310 transactions/day (2,155 enqueue + 2,155 ack), about 4,366 fsync/day extrapolated, and about 522 MiB/day of physical writes on this btrfs; `state.json` about 0.6 KB and `contexts.log` 204,521 B / 2,126 lines. Durability cost is accepted; cost is not a gate.
- Legacy `state.sqlite` migration was dropped deliberately: no confirmed installed base on the SQLite-era versions, so an upgrade starts a fresh cursor and re-reads from the gateway.
- Not yet done: merged into the main checkout; the live runtime still runs the previous code; WakaTime read-side verification (summaries/stats/heartbeats with an OAuth bearer token) still pending.

## Unreleased: windowed buffered direct send with an offline fallback (option A+B+ windowed, 2026-11-03, worktree `magpie-wakatime-ab`)

- Supersedes the option B and first A+B+ measurements below. `src/batching.mjs` and `test/batching.test.mjs` remain byte-identical to option A (sha256 `b7d8d4c6...` and `322d27fb...`); the implementation reuses A's `EnqueueBuffer`, `BATCH_ROWS=25`, `BATCH_WINDOW_MS=60s`, `stage`/`applyCommits` and `AckGate` unchanged.
- Windowing: `collectDay`/`readRange` accept a `limit` and return at most 25 mapped rows with a cursor that names exactly the processed prefix, including rows skipped as seen or filtered. Each window requires the head id unchanged, the total not decreasing (tail appends are allowed), and both the old and candidate cursor tails to match; an unstable window commits nothing. `scan` processes up to 32 windows per tick across backfill, today and reviews, so an 11,000-row backlog advances in 25-row steps instead of waiting for one whole result.
- Head insertion: when rows appear before the old head, the verified old prefix is never dropped. Intermediate front windows keep the old cursor on disk; a crash mid-front therefore re-reads only the newly inserted front, never the old prefix. Once the entire front is processed, one merged cursor names the front plus the verified old prefix at its new position, and only then do tail windows advance.
- Normal path: mapped rows accumulate in the same in-memory buffer as A. Nothing is sent until the buffer reaches 25 rows or 60 seconds from its first row. Each window is fed only the buffer's free room, so the buffer never exceeds 25 rows. A flush sends the buffer directly in requests of at most 25 rows through the existing WakaTime POST path. Rows answered with 2xx or a permanent 4xx are counted; the window cursor commits and `state.json` flushes once the buffer is handled. No heartbeat row enters `queue.sqlite`, and directly delivered rows leave no tombstone.
- Failure path: on a network error, 408, 429, 5xx or a per-item transient code, the flush stops and every unacknowledged row of that buffer (at most 25) is committed in one `Queue.enqueue` transaction, bypassing the 60-second enqueue window. The window cursor then commits, and the rows drain through the existing `AckGate`, retry/backoff and ack transactions. 401/403 durably enqueues the buffer remainder before pausing; if the queue cannot accept it, the buffer and cursor stay behind. A full queue blocks the flush, drains the backlog, and retries on a later tick.
- Restart attempts to drain the offline queue before reading new rows, then resumes from the cursor. The `AckGate` can hold a sub-25 trickle for up to 60 seconds before that drain. Buffered rows are not durable: a crash before a send re-reads them from the unchanged cursor, and the journal plus HMAC session ids reproduce the same payloads.
- Duplicate bound: same-head and tail windows are bounded by one current buffer/window, at most 25 rows; a 1,500-row result re-sends 25 rows after a one-window crash, not 1,500. A head-insertion crash is bounded by the new front rows already sent: the old cursor stays on disk for the whole front, so the verified old prefix is not re-read or re-sent (verified with 100 old rows + 100 inserted rows: 75–100 duplicates depending on the crash point, not 125). A crash between a failure enqueue and the cursor flush replays the same window after the queue drains. A cursor reset caused by a same-total mid-day rewrite or an unverifiable prefix can still replay a whole day.
- `bun test`: 117 pass, 0 fail.
- Bench (`bun bench/highwater.mjs`, 18,000 requests/day, 3 runs each). Success: 1,439 POSTs (one buffered flush per 60-second window), all 18,000 rows delivered, 0 enqueue and 0 ack transactions, 1,444 `state.json` flush writes, 12 fsyncs in the strace run, live `queue.sqlite` 4,096 B plus a 20,632 B WAL, `state.json` 788 B, median 65.8 MB (62.8 MiB) of physical writes (runs 65.8 / 53.5 / 69.6 MB; btrfs zstd variance). Failure injection `FAIL_EVERY=10`: 1,442 POSTs, 19,815 heartbeat attempts (1,815 failed rows re-sent through the queue), 144 enqueue and 144 ack transactions, 1,520 state flushes, 306 fsyncs in the strace run, live `queue.sqlite` about 840 KB plus a 4.15 MB WAL, median 107.0 MB (102.1 MiB) of physical writes (runs 86.3 / 107.0 / 107.5 MB; btrfs variance), queue ends pending 0 / acked 1,815.
- Comparison: option A measured about 2,876 commits and 418 MiB/day; option B about 2,155 POSTs and 88-93 MB/day with scan-sized duplicates; the first A+B+ about 1,439 POSTs and 65-88 MB/day with buffer-sized duplicates; the pre-A baseline about 4,310 commits and 522 MiB/day. The windowed version keeps A's 60-second cadence, removes A's queue commits on success, and makes the same-head crash bound exactly one 25-row window while keeping the old prefix across head insertions.
- Trade-off: a healthy minute performs one `state.json` cursor flush and one HTTP POST; each window costs a few source page reads (initial page, tail/head checks, window page, stability page). Large backfills progress at up to 800 rows per 30-second tick (32 windows).
